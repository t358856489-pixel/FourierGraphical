# 阶段 0 研究: 画布显示选项

**日期**: 2026-09-21 | **规范**: [spec.md](./spec.md) | **基础**: 功能 001 的 [research](../001-fourier-visual-editor/research.md)

技术栈沿用功能 001(TypeScript 6 + React 19 + Zustand + Canvas 2D), **不新增任何依赖**. 本功能没有技术选型上的未知项,
研究集中在三个设计问题: 长轨迹如何在章程原则 I 之下保持流畅、任意背景色下如何保证可辨识、旧数据如何兼容.

---

## R1. 保留轨迹的时间范围仍是 t 的纯函数

- **Decision**: 轨迹显示的时间区间由 `(显示选项, t)` 唯一确定:

  | 轨迹淡化 | 呈现模式 | 区间 |
  |---|---|---|
  | 开启(默认) | 任意 | `[max(0, t − trailSeconds), t]` —— 与现状完全相同 |
  | 关闭 | 二维绘图 | `[max(0, t − R), t]`, 其中 `R` = 保留时长; "全部"时 `R = 600`(FR-007 的上限) |
  | 关闭 | 波形 | `[max(0, t − trailSeconds), t]` —— 窗口不变, 只换亮度规则 (FR-003) |

- **Rationale**: 沿用功能 001 的做法——轨迹是区间上的采样, 而不是逐帧累积的点列. 因此拖动时间轴、循环回绕、
  视频导出、修改参数后整体重画(FR-004、FR-005)以及"重置即清空"(FR-006, 区间在 0 处截断)全部按构造成立, 无需额外逻辑.
- **Alternatives considered**: *每帧把当前点追加进数组*: 最简单, 但违反章程原则 I; 拖动时间轴、改参数、导出视频都会得到错误的轨迹.

## R2. 亮度用不透明的混色表达, 不用透明度

- **Decision**: 轨迹淡化关闭时, "正常亮度"是一个**不透明**的颜色 = 轨迹色与背景色按固定比例混合(`NORMAL_BRIGHTNESS_MIX = 0.55`,
  并由 R6 的对比度校验保证不低于 3:1). 最新 2 秒(`HIGHLIGHT_SECONDS`)分成 12 段, 颜色从正常亮度线性过渡到完整的轨迹色.
  绘制顺序为先旧后新. 轨迹淡化开启时的绘制代码一行不改(仍用透明度分段), 以保证 SC-007 的逐像素一致.
- **Rationale**: 保留的轨迹会大量自相交、自重叠(闭合图形反复描过同一条线). 如果用 `globalAlpha` 表达"较暗",
  重叠处会叠加变亮, 违反 FR-002b"早于 2 秒的轨迹一律以正常亮度显示". 不透明颜色重叠多少次都是同一个颜色.
  这也让 R4 的"只采样一个周期"成为可能——盖住自己不会改变画面.
- **Alternatives considered**: *透明度 + 离屏层合成后整体降低不透明度*: 能避免叠加变亮, 但多一张全尺寸离屏画布与一次合成, 且高亮段与正常段的交界需要特殊处理.

## R3. 长区间下的采样: 点数预算 + 按 2 的幂放大步长

- **Decision**: 基础步长仍为 `1 / max(60, 32·max|f|)`. 当区间长度 ÷ 步长超过点数预算 `RETAINED_TRAIL_POINT_BUDGET = 40 000` 时,
  步长取 `基础步长 × 2ⁿ`, `n` 为使点数不超过预算的最小整数. 采样点仍落在绝对时间网格 `k·step` 上.
- **Rationale**:
  - 预算: 40 000 点 × 50 个分量 ≈ 200 万次分量求值, 桌面约 30–50 ms, 满足 SC-004"拖动参数后 100 ms 内整体更新". 稳态播放由缓存(R5)承担, 每帧只算新进入的几个点.
  - 为什么是 2 的幂: "全部"模式下区间随 `t` 增长, 若步长连续变化, 网格每帧都在平移——缓存全部失效, 且轨迹上的采样点会"游动"(可见的闪烁).
    2 的幂使步长在很长一段时间内不变, 且新网格是旧网格的子集(偶数下标), 放大时缓存里一半的点可以直接复用.
- **稀疏采样下的平滑 (FR-008)**: 当每圈采样数低于 16 时, 折线改用"过相邻采样点中点的二次曲线"绘制(`quadraticCurveTo`), 8 点/圈时仍然圆滑.
  每圈采样数低于 8(只会出现在"高频 + 不成整数比 + 保留数分钟"的组合)时, 在保留时长控件旁提示"轨迹已简化显示".
- **Alternatives considered**:
  - *不设预算*: 100 圈/秒 × 600 秒 = 192 万点, 改一次参数要数秒, 直接否决.
  - *把预算提高到 15 万点*: 编辑后重算约 120–150 ms, 超出 SC-002/SC-004.
  - *拖动期间先粗采样、松手后补细采样(LOD)*: 能进一步提高拖动时的帧率, 但同一 `(函数, t)` 会先后画出两种画面, 是对章程原则 I 的有限偏离.
    **本期不采用**; 仅当 R8 的基准不达标时作为后备, 且采用前必须记入 plan.md 的"复杂度跟踪".

## R4. 周期性函数只采样一个周期

- **Decision**: 纯函数 `periodOf(fn): number | null`. 当所有启用分量的振幅、频率、相位都是固定值时, 把频率按取值精度(0.001)化为整数
  `mᵢ = round(1000·fᵢ)`, 周期 `P = 1000 / gcd(|mᵢ|)` 秒(全部为 0 时图形静止, 取 `P = 0`). 存在关键帧轨道时返回 `null`.
  轨迹淡化关闭且 `P` 小于区间长度时, 采样区间收缩为 `[t − P, t]`.
- **Rationale**: 这是最常见的真实场景——三种预设和示例函数都是基频 0.2 的整数倍, 周期 5 秒. "全部"保留 10 分钟时只需采样 5 秒(约 1 300 点),
  而不是 4 万点, 且画面**完全相同**: 闭合曲线之后的每一圈都精确盖在第一圈上, 而 R2 保证了重叠不改变颜色.
  `periodOf` 只依赖 `fn`, 因此仍是纯函数, 不违反原则 I.
- **边界**: `1.37` 与 `2.5` 这类频率得到 `P = 100` 秒, 同样受益; 若 `P` 不小于区间长度则没有收益, 走 R3 的预算路径. 高亮的 2 秒始终取 `[t − 2, t]`, 与周期无关.
- **Alternatives considered**: *用浮点容差判断频率比是否为有理数*: 结果依赖容差且不稳定; 输入本来就有 0.001 的精度, 直接用整数 gcd 是精确的.

## R5. 轨迹缓存的扩展

- **Decision**: 沿用 `src/render/trailCache.ts` 的网格点缓存, 增加两点: (a) 缓存键加入步长的幂次 `n`; `n` 增大时保留偶数下标的点并重新编号, 而不是清空;
  (b) 区间起点为 0 的"全部"模式下不做左侧裁剪以外的任何淘汰. 契约不变: 缓存结果必须与 `sampleTrail` 的整体重算**逐点相等**, 并有测试证明(章程原则 I).
- **Rationale**: 稳态播放每帧只新增 `步长⁻¹/60` 个点(通常 4–5 个), 与保留时长无关.

## R6. 由背景色派生整套画布配色

- **Decision**: 纯函数 `derivePalette(background, baseTheme): RenderTheme`:
  1. `background === null`(默认)时**原样返回** `baseTheme`——这是 SC-007"默认画面逐像素不变"的保证.
  2. 否则按 WCAG 相对亮度判断背景深浅(阈值 0.179, 即黑白两种前景对比度相等的点), 选"墨色" = 白或黑.
  3. 网格、主网格、坐标轴、圆、向量、文字、轨迹: 各自以固定比例把背景色向墨色混合(轨迹保留其色相: 取基础轨迹色, 再向墨色调整);
     然后用二分法加大混合比例, 直到对比度 ≥ 3:1(文字 ≥ 4.5:1). 黑或白相对任何背景至少有一个 ≥ 4.58:1, 所以二分一定收敛.
  4. 12 个分量色: 对比度 ≥ 3:1 的原样保留; 不足的沿"向墨色混合"的方向二分调整到恰好达标. 只改明暗、不改色相,
     因此与分量列表里的色标仍然对得上(FR-019). 面板上的色标不变.
- **颜色解析**: 纯函数 `parseColor(text)` 支持 `#RGB`、`#RRGGBB` 以及设计令牌使用的 `oklch(L% C H)`(约 25 行的 OKLCH→sRGB 转换, 无 DOM 依赖).
  用户输入只接受十六进制(取色控件本身就产出 `#rrggbb`); 其他写法按 FR-020 提示格式并保留上一个有效值.
- **Rationale**: 纯函数 + 无 DOM 使它可以用性质测试穷举: 对任意背景色, 断言每种线条 ≥ 3:1、文字 ≥ 4.5:1(SC-003). 同一背景色总得到同一套配色(规范"画布配色方案"实体的要求).
- **Alternatives considered**:
  - *只提供深/浅两套固定配色*: 中等明度的背景(如中灰、饱和的蓝)下两套都可能不达标.
  - *用 1×1 离屏画布让浏览器解析颜色*: 引入 DOM 依赖, 无法在纯函数里做性质测试, 且不同浏览器的色域处理可能有差异.
  - *给撞色的分量加描边*: 规范允许, 但描边会改变线宽观感并使绘制调用翻倍; 调整明暗更简单.

## R7. 网格与坐标轴拆分

- **Decision**: `drawGrid(ctx, region, viewport, theme, { grid, axes, verticals })`. 对世界坐标为 0 的那条线: `axes` 开启时用坐标轴色;
  `axes` 关闭而 `grid` 开启时按普通网格线的规则着色(它是第 0 条, 属于主刻度线)——因此不会出现缺口(FR-012).
  波形区的零值基准线归 `axes`, 时间刻度线归 `grid`(FR-010、FR-011).
- **Rationale**: 改动局限在一个函数的着色分支与 `drawFrame` 的两处条件.

## R8. 性能验证

- **Decision**: 扩展 `tests/perf/render-benchmark.spec.ts`, 新增三个场景, 全部为 50 个分量、轨迹淡化关闭、"全部"、`t = 600`:
  (a) 周期函数播放; (b) 不成整数比的函数播放(走满 4 万点预算); (c) 场景 b 下每帧修改一次参数. 判据: a、b 的 p95 帧间隔 < 25 ms; c 的 p95 < 100 ms.
- **后备方案(仅当 b 不达标时)**: 每帧描 4 万点的折线是主要成本. 后备为"分块离屏层": 把正常亮度的轨迹按绝对网格每 256 点一块, 画进一张离屏画布;
  只有完整的块才入层, 未满的一块与高亮段每帧直接画. 因为块的划分只取决于绝对网格, 无论是逐帧追加还是整体重建, 入层的绘制调用序列完全相同——
  画面与历史无关, 满足原则 I. 代价是 `drawFrame` 需要一个由调用方持有的层缓存, 且实时画面与导出都必须走同一条"经由离屏层"的路径才能逐像素一致.
  **先不实现**(章程原则 VI: 不为尚不存在的需求构建抽象); 若采用, 记入"复杂度跟踪".

## R9. 显示选项的存储与旧数据兼容

- **Decision**: 在 `ViewSettings` 增加四个字段(见 data-model). 它们随草稿保存(`draft.view`), **不进入** `FourierFunction`, 已保存函数的 schema 与 `schemaVersion` 不变(FR-023a).
  `draftSchema` 中的 `view` 改为"先补默认值再严格校验": 缺 `showAxes` 时取 `showGrid` 的值(FR-024 与故事 2 场景 6), 缺 `trailFade` 取 `true`, 缺 `trailRetention` 取 `'all'`, 缺 `background` 取 `null`.
- **Rationale**: 现有 `draftSchema` 是严格对象, 既会拒绝未知字段、也会拒绝缺失字段. 不做这一步, 所有老用户升级后的草稿都会被判为"已损坏"而丢失——正是 SC-006 要防止的.
- **Alternatives considered**: *给草稿加版本号并写迁移函数*: 更正规, 但当前只有一次、且只是补默认值的变更; 等出现第二次不兼容变更时再引入.

## R10. 界面

- **Decision**: 工具栏的显示开关组改为: 向量、圆、轨迹、**网格**、**坐标轴**; 其后新增一个"画面"按钮, 展开一个非模态的面板(`<details>`/disclosure 语义), 内含:
  轨迹淡化开关; 保留时长选择(原生 `<select>`: 5 秒、10 秒、30 秒、1 分钟、2 分钟、5 分钟、10 分钟、全部; 淡化开启时 `disabled` 并附说明, FR-002c);
  达到上限或已简化显示时的状态说明(FR-007、R3); 背景色: 四个预置色块、原生 `<input type="color">`、十六进制输入框、"恢复默认".
- **Rationale**: 工具栏在窄屏下已经换行, 再加 5 个控件会把画布挤小; 最常用的两个新开关(网格、坐标轴)留在外面以满足 SC-001"不超过 2 次操作", 其余放进一个面板: 打开面板 + 操作 = 2 次.
  全部使用原生表单控件, 键盘与读屏支持由浏览器保证(章程原则 IV). 色块是带可访问名称的按钮, 并用 `aria-pressed` 表示当前选中.
- **保留时长用离散档位而非连续滑块**: 5 秒到 10 分钟跨两个数量级, 线性滑块在低端无法精细选择; 对数滑块的读数不直观. 8 个档位覆盖了有意义的选择, 且"全部"天然是其中一档.

## R11. 导出

- **Decision**: 导出对话框构造 `FrameInput` 时, `view` 已含新字段, `theme` 改为 `derivePalette(view.background, 基础主题)`——与舞台循环用同一个函数.
- **Rationale**: `drawFrame` 本来就是实时画面与导出共用的唯一入口, 新选项自动作用于成片(FR-022、SC-005). 起点不为 0 的视频导出同样正确:
  每一帧的轨迹区间由 R1 从该帧的 `t` 算出, 第一帧就包含此前应有的完整轨迹(规范边界情况).

## R12. 测试策略

- **先固化现状**: 第一个任务是在**未改动**的代码上录制 `drawFrame` 默认设置下的调用序列快照与一张端到端截图基线; 之后所有改动都必须让它们保持不变(SC-007).
- **单元 / 性质测试**: `parseColor`、`contrastRatio`、`derivePalette`(任意背景色下的对比度下界; 默认背景原样返回)、`periodOf`、轨迹区间与步长(2 的幂、预算、网格子集关系)、
  缓存与整体重算逐点相等(含步长放大时)、`drawGrid` 四种开关组合、保留模式的颜色分段(无透明度)、草稿 schema 对旧数据的补默认值.
- **端到端**: 每个用户故事一份; 沿用功能 001 的截图指纹方法验证"拖到 t 与连续播放到 t 逐像素一致"在轨迹淡化关闭时同样成立; axe 检查展开"画面"面板后的状态.

---

**结论**: 没有遗留的 NEEDS CLARIFICATION. 规范推迟到规划阶段的两项已确定: 颜色输入只接受十六进制(R6); 过渡 2 秒、正常亮度为 55% 混色并以 3:1 对比度为下界(R2、R6).
