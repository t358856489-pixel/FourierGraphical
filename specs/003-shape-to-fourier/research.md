# 阶段 0 研究: 从图形得到傅立叶函数

**日期**: 2026-09-24 | **规范**: [spec.md](./spec.md) | **基础**: 功能 [001](../001-fourier-visual-editor/research.md)、[002](../002-canvas-display-options/research.md)

技术栈不变(TypeScript 6 + React 19 + Zustand + Canvas 2D), **不新增运行时依赖**. 未知项集中在: 路径→分量的数学、SVG 的本地解析、
手绘的平滑与重采样、把上限提到 200 后的性能.

---

## R1. 路径 → 分量: 对闭合路径做离散傅立叶变换

- **Decision**: 把闭合路径按弧长均匀重采样为 `N` 个复数点 `z_k = x_k + i·y_k`(`N` 取 1024, 或路径点数的下一个 2 的幂, 上限 4096),
  做 DFT 得到系数 `c_n = (1/N)·Σ z_k·e^(−2πi·nk/N)`, `n ∈ [−N/2, N/2)`. 每个 `c_n` 对应一个分量: 振幅 `|c_n|`、频率 `n·f₀`(`f₀ = 0.2`, 与预设一致)、
  相位 `arg(c_n)`(度). 按 `|c_n|` 从大到小取前 `count` 个, **只从 `|n| ≤ FREQUENCY_RANGE.max / f₀ = 500` 的项中选**(否则频率会超出 ±100 圈/秒, 生成的函数无法通过 schema 保存——分析报告 F1); `c_0`(直流/重心)**不作为分量**, 而是在归一化时去掉(FR-005 的居中).
  求和顺序与现有求值器一致: `tip(t) = Σ A·(cos θ, sin θ)`, `θ = 2π·(phase/360 + f·t)`. `N ≤ 4096` 时直接 O(N·M)(M = 分量数 ≤ 200)计算所需系数即可, 约 80 万次复数乘加, 远低于 SC-003 的 1 秒; 不需要 FFT.
- **Rationale**: 这是标准的"傅立叶画图"数学: 一个周期内 `Σ c_n·e^(2πi·n·f₀·t)` 精确重建采样点(取全部系数时), 截断到前 `count` 个就是最小二乘意义下的最佳逼近, 天然满足 FR-002"按贡献排序"与 FR-003 的偏差界. 负频率必不可少——只取正频率只能画出一类特殊曲线. 现有 `HarmonicComponent` 的三个参数刚好一一对应, **不需要新增字段**(FR-008、SC-005).
- **Alternatives considered**: *只用正频率 + 对 x、y 分别做级数*: 与现有"一串旋转向量"的模型不符, 需要两组向量. *FFT 库*: 新增依赖且规模用不上.

## R2. 归一化与坐标约定

- **Decision**: 转换前把路径平移到重心为原点、按包围盒的长边缩放到 `TARGET_EXTENT = 2`(与示例函数振幅之和相当). **`normalize` 不翻转 y 轴**: `ShapePath` 一律约定为世界坐标(y 向上); 来自屏幕坐标的手绘与 SVG 由各自的来源层在传入前翻转, 内置图形本来就是世界坐标——否则心形与字母 F 会倒过来(分析报告 F2). 相位精确到 0.1°、振幅到 0.001 后写入(与 `ranges.ts` 的步长一致); 低于 `1e-4` 的振幅直接丢弃.
- **Rationale**: FR-005; 画布本来就按 `boundingRadius` 自动适配, 统一尺寸让"应用后立刻看到图形"稳定. 量化到输入精度使转换结果可以原样保存与再编辑.

## R3. 分量上限 50 → 200 的影响面

- **Decision**: 只改 `MAX_COMPONENTS = 200`; 它已被 schema、`addComponent`、`applyPreset`、分量面板的计数与禁用逻辑共享, 无其他硬编码(已用 grep 核实). 配套:
  (a) 轨迹点数预算按分量数自适应: `RETAINED_TRAIL_POINT_BUDGET` 由 40 000 改为 `min(40 000, 2 000 000 / 启用分量数)`(200 个分量时 10 000 点), 使"编辑后整体重算"的三角函数次数上限不变(约 200 万次);
  (b) 淡化模式的 `DEFAULT_MAX_TRAIL_POINTS` 同样按 `min(4 000, 400 000 / 分量数)` 自适应;
  (c) 分量面板在超过 60 项时启用列表虚拟化——**不引入依赖**, 用 `IntersectionObserver` 只渲染可视区附近的行(每行高度固定), 因为 200 行 × 每行 3 个滑块 + 3 个数值框 ≈ 1 200 个受控输入, 已知会拖慢每次 store 更新后的协调;
  (d) 性能基准新增 200 分量的场景(播放、每帧编辑、保留"全部"), 判据与功能 002 相同.
- **Rationale**: 章程原则 V. 求值成本与分量数成正比, 采样点预算反比缩放即可保持总量; 面板是新的风险点, 虚拟化是最小改动.
- **Alternatives considered**: *把上限设为 200 但不动预算*: 200 分量下编辑后整体重算约 120–200 ms, 违反 SC-002 的 100 ms. *Web Worker 求值*: 后备方案, 先不做.

## R4. 内置图形的路径生成

- **Decision**: 每个内置图形是一个纯函数 `path(): Vec2[]`, 生成有序闭合点列: 雪花 = Koch 曲线 3 阶(6 段 × 4³ = 384 条边, 正好 6 个主尖角、每边 3 级细节); 五角星 = 内外半径比 0.382 的 10 个顶点; 心形 = 参数方程 `x = 16 sin³t, y = 13 cos t − 5 cos 2t − 2 cos 3t − cos 4t`; 圆、正三/四/六边形 = 等分点; 字母 F = 手工定义的 10 个顶点的多边形(不对称, 可看出描绘方向). 折线的顶点之间按弧长插值到 R1 的采样密度. 缩略图由同一个 `path()` 画成内联 SVG(FR-010).
- **Rationale**: 无外部资源、可测试(顶点数、对称性、闭合)、缩略图与轨迹必然一致.

## R5. 手绘: 采样、平滑、重采样

- **Decision**: `pointermove` 以屏幕坐标采点(不丢帧, 用 `getCoalescedEvents` 取合并事件), 去掉相邻距离 < 1 px 的重复点. 松手后: (1) 闭合(追加起点); (2) 按弧长均匀重采样为 512 点; (3) **平滑**: 对重采样后的闭合点列做循环移动平均, 窗口宽度 = `1 + 2·round(smoothing · 12)`, `smoothing ∈ [0, 1]`(滑块 0–100, 默认 25 → 窗口 7 点); 0 时不平滑; (4) 再交给 R1. 拓扑不变: 移动平均不会消除自相交(只会缩小环). 最短有效路径: ≥ 20 个原始点且长度 ≥ 画布短边的 5%(FR-013).
- **Rationale**: 先按弧长重采样再平滑, 使平滑程度与画的快慢无关(FR-014a); 循环窗口保证闭合处也平滑. 512 点足以表达手绘细节又远小于 R1 的上限. 原始点列保留在绘制会话里, 滑块与分量数改变时从原始点重新走 (2)–(4)+R1, 2000 点在 10 ms 内完成, 因此"即时"重转换可行(FR-014b).
- **Alternatives considered**: *Ramer–Douglas–Peucker 简化*: 去点不去抖, 且与"平滑程度"的语义不符. *Catmull-Rom 拟合*: 更圆润但会改变形状, 用户不可控.

## R6. SVG 导入: 本地、防御性解析

- **Decision**: 用浏览器内置 `DOMParser` 以 `image/svg+xml` 解析文本(**不插入文档**, 不执行脚本、不加载外部资源); 只读取 `<path d>`, 以及 `<polygon>`/`<polyline>`/`<rect>`/`<circle>`/`<ellipse>`/`<line>` 转成等价路径. 自写一个约 150 行的 `d` 属性解析器, 支持 M/L/H/V/C/S/Q/T/A/Z 及相对坐标; 贝塞尔按固定 16 段、圆弧按角度每 5° 一段展平, 再按弧长均匀重采样. 取周长最长的一条(FR-015); 应用祖先 `transform` 中的 `translate/scale/rotate/matrix`(不支持 `skew`, 遇到时忽略并告知). 限制: 文件 ≤ 2 MB, 展平后点数 ≤ 100 000, 超出即拒绝(FR-017/018). 解析在主线程做, 但按每 5 000 点让出一次事件循环并显示进度(FR-018); 全部失败路径返回 `Result`.
- **Rationale**: 章程"纯本地、无网络"与安全约束; `DOMParser` 的独立文档不会执行 `<script>` 或 `onload`, 也不会请求 `<image href>`. 自写 `d` 解析器比引入 svg 库更小且完全可测.
- **Alternatives considered**: *`SVGPathElement.getPointAtLength`*: 需要把元素插入文档才能测量, 有渲染副作用且不同浏览器精度不同. *第三方 SVG 解析库*: 新增依赖.

## R7. 应用生成的函数

- **Decision**: 复用 `documentStore.applyEdit(next, 'commit')`(可撤销, FR-006), 由一个 `applyGenerated(components)` 动作封装: 替换 `components`、`presentationMode = 'drawing2d'`; 随后 `playbackStore.reset()` + `play()`(FR-007; `prefers-reduced-motion` 下不 play 而 `seek(1 / PRESET_BASE_FREQUENCY)`——用常量算周期, 不写死 5), `viewStore` 置 `showTrail = true, trailFade = false, trailRetention = 'all'`(FR-007a). 覆盖确认沿用 `PresetPicker` 的 `ConfirmDialog` 逻辑, 抽成一个共用 hook `useOverwriteGuard`.
- **Rationale**: 全部走既有动作, 不引入新的状态路径; 撤销一步恢复到应用前的函数(显示选项不在撤销范围, 这与功能 002 一致, 记入 quickstart).

## R8. 界面

- **Decision**: 分量面板头部在"预设波形"旁增加"图形"入口, 打开一个对话框(复用 `Dialog`), 三个页签: **图形库**(缩略图网格 + 分量数滑块 2–200, 选中即预览应用)、**手绘**(关闭对话框进入画布的绘制模式, 由 `Stage` 上的一层绘制层承担: 显示笔迹、"完成/清除/退出"按钮、平滑滑块与分量数滑块)、**导入**(文件选择器 + 拖放区). 绘制模式中 `useStagePointer` 的向量拖拽与缩放平移禁用, 指针事件交给绘制层.
- **Rationale**: 图形库与导入是一次性的选择, 适合对话框; 手绘需要整块画布, 只能在舞台上做.

## R9. 测试策略

- 单元: DFT 对已知曲线(圆 → 单个分量; 正 n 边形 → 频率 1, n−1, n+1, … 的分量; 逆变换重建误差 FR-003); 归一化; Koch/星形/心形的点数与闭合; 平滑窗口与拓扑; `d` 解析器逐指令用例 + 畸形输入(超长数字、缺参数、非法字母、`<script>`、外部 href)全部返回错误而不抛异常; 上限 200 下 schema、addComponent、applyPreset 的边界.
- 性质测试: 任意闭合点列 → 转换 → 用全部系数重建 → 逐点误差 < 1e-6; 平滑不改变点数与闭合.
- 组件: 图形库对话框、绘制层(用合成指针事件画一个方形)、导入区的错误提示.
- 端到端: 三个故事各一份; 200 分量的性能基准; 默认画面回归(功能 002 的快照与截图基线继续作为护栏).
